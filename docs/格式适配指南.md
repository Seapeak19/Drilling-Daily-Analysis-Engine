# 格式适配指南：如何让解析器支持一种新的钻井日报格式

> 面向：接手本项目、需要新增日报格式的开发者。
> 目标：**只改配置、不改抽取逻辑**就能支持新格式（项目计划书 8.1「日报格式碎片化」的应对方案）。

---

## 0. 先判断属于哪种情况

| 情况 | 需要做什么 | 预计工作量 |
|---|---|---|
| **A. 版式不同，但字段语义相同**（最常见的真实情况） | 在 `TEMPLATE_SIGNATURES` 加签名 + `TEMPLATE_SPECS` 加标签表 | 30–60 分钟 |
| **B. 出现新的作业描述写法**（如"倒划眼""甩钻具"） | 只需在 `schema/code-map.json` 的 `aliases` 里加词 | 5 分钟 |
| **C. 出现新的单位写法**（如 `kg/cm2`、`lb/ft3`） | 在 `src/ddr/units.py` 加一条换算分支 + 单测 | 15 分钟 |
| **D. 表格结构特殊**（无表格线、多级表头、横向排布） | 需要写一个新的抽取函数（见第 4 节） | 半天 |

**判断方法**：先跑 `ddr parse 新日报.pdf --no-validate --quiet`，看 `source.template_id` 与 `source.warnings`：

- `template_id = "unknown"` → 情况 A（或 D）
- `template_id` 识别正确但某些字段为空 → 情况 A 的标签表不全
- 字段抽到了但分类错误 → 情况 B
- 数值量级明显不对 → 情况 C 或单位配置缺失

---

## 1. 情况 A：登记一种新格式

### 1.1 加模板签名（`src/ddr/detect.py`）

```python
TEMPLATE_SIGNATURES.append(
    TemplateSignature(
        template_id="xx_operator_v2",              # 唯一 ID
        label="XX 作业者日报 v2",
        anchors=[                                   # 用于识别模板的关键词（尽量选不会出现在别的模板里的）
            r"XX作业者钻井日报",
            r"时效记录表",
            r"钻头使用情况",
        ],
        unit_hint="metric",                         # 该模板默认单位制；不确定就写 "unknown"
        min_hits=2,                                 # 至少命中几个锚点才算识别成功
    )
)
```

> **经验**：锚点优先选**表头行**里的字段名（如"时效记录表"），不要选通用词（如"钻井日报"）。
> 锚点命中率低于 50% 时识别置信度会很低，建议补足到 4–6 个。

### 1.2 加模板配置（`src/ddr/extract.py` 的 `TEMPLATE_SPECS`）

```python
"xx_operator_v2": TemplateSpec(
    template_id="xx_operator_v2",
    label="XX 作业者日报 v2",
    # 以下是"内容签名"：用于在文档里找到目标表格，**不依赖表格序号**
    time_column_signature=["作业内容", "历时", "hours"],   # 一般不用改
    bit_column_signature=["进尺", "footage", "磨损"],       # 一般不用改
    mud_column_signature=["密度", "density", "取样点"],     # 一般不用改
    # 表头标签 → 字段键的映射。左侧写日报里实际出现的写法（可多种）
    header_labels=[
        (["井号", "井 号", "well name"], "well_name"),
        (["作业者"], "operator"),
        (["井深", "井 深"], "md_m"),
        (["当日进尺"], "progress_m"),
        # ... 参见现有模板的完整字段清单
    ],
    # 如果该模板是"英文模板 + 公制数值"这类混用情况，显式声明各区块单位：
    header_unit_overrides={"depth": "m", "footage": "m", "rop": "m/h"},
    bit_unit_overrides={"depth": "m", "footage": "m"},
    mud_unit_overrides={},   # 留空表示"以表格列头标注的单位为准"
),
```

### 1.3 字段键清单（可用的目标字段）

| 字段键 | 含义 | 期望单位 |
|---|---|---|
| `well_name` / `operator` / `contractor` / `rig` / `field` | 表头文本 | 文本 |
| `api_number` / `uwi` | 井标识 | 文本 |
| `md_m` / `tvd_m` | 测量井深 / 垂深 | m |
| `progress_m` | 当日进尺 | m |
| `hole_diameter_in` | 井眼直径 | in |
| `rop_av_m_per_h` | 平均钻速 | m/h |
| `etim_drill_h` | 钻进时间 | h |
| `etim_spud_days` | 开钻天数 | 天 |
| `report_no` / `report_date` / `dtim_spud` | 报表编号 / 作业日期 / 开钻日期 | — |
| `well_status` | 井况 | 文本 |

**没有对应字段键时**：先在 `FIELD_ALIASES` 里加通用别名；若确实需要新字段，
在 `src/ddr/model.py` 的 `ReportHeader` 里加属性，并同步更新
`schema/ddr-report.schema.json`（否则 Schema 校验会失败）。

### 1.4 验证

```bash
ddr parse 新样本.pdf --out out/new.json --summary     # 看抽取结果与时效小结
ddr parse 新样本.pdf --strict                         # Schema 校验必须通过
```

然后把它加入评测集（见第 5 节），跑 `ddr eval` 确认字段准确率。

## 2. 情况 B：新的作业描述写法

只改 `schema/code-map.json`，找到对应的操作码，往 `aliases` 里加词：

```json
"TRIP_OUT": {
  "aliases": ["起钻", "trip out", "pooh", "甩钻具", "倒划眼起钻"]
}
```

**必须注意的三条规则**（都是踩过的坑）：

1. **匹配按"最长别名优先"**。所以更具体的写法要写得更长，例如 `循环洗井` 会赢过 `循环`。
2. **否定式与等待语境有独立守卫**（`src/ddr/codes.py` 的 `_NEGATIVE_RE` / `_WAIT_PREFIXES`）。
   若新格式用别的否定词（如"未出现""不存在"），要补进 `_NEGATIVE_RE`。
3. **高严重度 NPT 有强制覆盖**（`_NPT_OVERRIDE`：卡钻/井控/井漏/打捞/坍塌）。
   这些词一旦出现就是当日主要 NPT，不会被句子里的动作词降级。

验证方式：

```bash
ddr info          # 打印全部操作码与别名数量，确认新词已加载
pytest tests/test_codes.py -q
```

**新增操作码**时（不是加别名），要同时改三处：
`schema/code-map.json`（定义）、`schema/ddr-report.schema.json` 的
`time_log.code.enum`（枚举）、`src/ddr/extract.py` 中需要的话加列名映射。

## 3. 情况 C：新的单位写法

在 `src/ddr/units.py` 里：

1. 在对应函数（`length_to_m` / `force_to_kgf` / `density_to_gcc` …）加一个分支；
2. 在 `src/ddr/normalize.py` 的 `UNIT_KIND` 里登记该单位属于哪一类；
3. 在 `tests/test_units.py` 加一条用**独立复算值**的断言（不要引用实现里的常量，否则测试与实现同源，等于没测）。

```python
# units.py
if u in ("kg/cm2", "千克/平方厘米"):
    return float(value) * 98.0665  # → kPa
```

**单位判定优先级**（`normalize.resolve_number`，改动前务必理解）：

```
① 值自带单位（"2350.0 m"）
② 模板区块级覆盖（source_unit_override，如 iadc_classic 的表头区块声明为 m）
③ 列头/标签自带单位（"Depth (ft)"、"MW (ppg)"）
④ 模板默认单位（TEMPLATE_SOURCE_UNITS）
⑤ 判定不出来 → 返回 None 并记警告，绝不默认公制
```

> **为什么②在③前面**：真实日报里"模板是英文的、数值却是公制的"很常见。
> 区块级覆盖是**人工确认过的事实**，比可能过期的列头文字更可靠。
> 但如果某个区块内部各列单位不同（如泥浆区块一部分 ppg 一部分 g/cm³），
> 就不要写区块覆盖，让③逐列生效。

## 4. 情况 D：表格结构特殊

现有抽取依赖 `reader.py` 提供的三种输入形态：

| 形态 | 来源 | 说明 |
|---|---|---|
| `Document.tables` | pdfplumber 的框线识别 / Excel 的"按空行列切分" | 首选 |
| `Document.pages[].lines` | 文本行（PDF 或 Excel 行拼接） | 退化路径 |
| `Document.xlsx_grids` | 原始单元格网格 | 需要精确坐标时用 |

新增特殊结构时的做法：

1. 在 `reader.py` 里把该结构**归一成 `Table`**（推荐），这样上层抽取器不用改；
2. 若无法归一，就在 `extract.py` 里新增一个 `extract_xxx` 函数，并在
   `pipeline.parse_document` 里按 `detection.template_id` 分派。

**务必保留的行为约定**：
- 抽不到的字段写 `None`，不要写空字符串或 0（下游无法区分"没读到"和"读到 0"）；
- 单位判定不出来时保留原始值并记 warning，不要静默丢弃、也不要猜；
- 所有数值字段走规则抽取，**不得交给 LLM**。

## 5. 把新格式纳入评测集

真实日报到位后（这是阶段 0 的原本计划）：

```bash
# 1. 把文件放到 data/samples/samples/，并写对应的 ground truth
#    data/samples/ground_truth/<同名>.truth.json
# 2. 在 data/samples/manifest.json 的 items 里登记一条：
```

```json
{
  "file": "samples/新样本.pdf",
  "truth": "ground_truth/新样本.truth.json",
  "template_id": "xx_operator_v2",
  "well_name": "XX-1",
  "report_no": 12,
  "report_date": "2026-03-01",
  "phase": "drilling",
  "unit_system": "metric",
  "synthetic": false
}
```

ground truth 的结构：**井级信息在顶层，日报级信息在 `truth` 里**：

```json
{
  "template_id": "xx_operator_v2",
  "well_name": "XX-1",
  "operator": "...",
  "contractor": "...",
  "rig": "...",
  "report_date": "2026-03-01",
  "truth": {
    "report_no": 12, "md_m": 2350.0, "tvd_m": 2100.0, "progress_m": 120.0,
    "etim_drill_h": 10.0, "rop_av_m_per_h": 12.0, "sum_hours": 24.0,
    "npt_hours": 4.0,
    "time_log": [{"hours": 10.0, "code": "DRILL", "operation": "旋转钻进", "npt_category": null}],
    "npt_events": [], "connections": [], "connection_count": 0,
    "bit_records": [], "mud": {"density_gcc": 1.25, "funnel_viscosity_s": 45, "fl_ml": 4.0},
    "phase": "drilling", "unit_system": "metric"
  }
}
```

> **标注纪律**：ground truth 必须与日报**印出来的内容**逐字一致。
> 拿不准的字段就留空（评测器会自动跳过 `expected` 与 `actual` 都为空的项），
> 不要"按常识补一个合理值"——那会让准确率数字失去意义。
> 合成数据可以用 `ddr check` 自动校验一致性；真实数据目前只能人工核对。

## 6. 回归检查清单

改完任何一种格式，跑完这三条再提交：

```bash
pytest tests -q                                   # 单元 + 端到端
ddr check  --data data/samples/dataset.json        # ground truth 自检（合成集）
ddr eval   --data data/samples                     # 分字段准确率（不得下降）
ddr robust                                         # 畸形日报行为契约（不得回归）
```

**准确率下降时**：先看 `data/samples/evaluation_report.md` 的"未通过项明细"，
再对照"逐字段准确率"表定位是哪个字段的问题，而不是先怀疑数字。
